# Обновление Desktop SDK для безопасной отправки голосовых

## Что меняется

Плагин использует `host.retainSession(storedSessionId, capturedOwner)`. Этот SDK-метод получает владельца через существующий native resolver Hermes и удерживает его соединение между `session.resume` и `file.attach`. Известный адресат записи не меняется при переключении фокуса. Отсутствующий при начале записи owner разрешается заново при Send и каждом явном повторе.

Тот же patch исправляет `composer.submit`: видимый, но заблокированный composer или поверхность без принимающего обработчика возвращает `false`. Плагин сохраняет WAV. Подтверждение означает приём для dispatch/queue/steer, не ответ backend или модели. Применяй весь patch, не один новый SDK-метод.

Это изменение **клиента Hermes Desktop**, не серверный Python-плагин. Установка файлов на удалённый backend не обновляет SDK Windows-клиента.

## Готовый Windows-клиент

Для Windows x64 доступен portable-клиент, в котором **SDK/composer patch и сам плагин уже собраны вместе**. Запускай `Start-Voice-Note.cmd` из полного архива; отдельная установка плагина через Git не нужна. Подробности — [WINDOWS-CLIENT.ru.md](WINDOWS-CLIENT.ru.md). Это неофициальная Hermes Light сборка для существующего удалённого backend; переустановка плагина в прежнем окне её не заменяет.

## Установка в клиент из исходников

В комплекте выпуска: `install/hermes-desktop-session-transport.patch`.

1. Отправь или отмени незавершённую запись перед перезапуском/обновлением плагина. Старая версия хранит WAV только в памяти.
2. Открой терминал в корне **исходников Windows-клиента**, где существует `apps/desktop/package.json`. Не в каталоге профиля и не на удалённом backend.
3. Укажи фактический путь к скачанному patch в переменной `$SdkPatch` и проверь применимость. Пример для PowerShell:

```powershell
$SdkPatch = Read-Host 'Полный путь к hermes-desktop-session-transport.patch'
git apply --check -- $SdkPatch
```

4. Только если проверка завершилась успешно, примени patch:

```powershell
git apply -- $SdkPatch
```

5. Собери обновлённый клиент обычным способом. В проверенном исходном Desktop package используются Node >=26, установка зависимостей через `pnpm install --frozen-lockfile` из корня репозитория и сборка через `pnpm --dir apps/desktop build`. Patch сам не запускает сборку, службу, модель или приложение.
6. Для автоматического включения в собственную сборку помести исходный `plugin.js` в `apps/desktop/src/plugins/hermes-voice-note/plugin.js` перед build: это штатный bundled-plugin путь. Либо установи отдельный плагин через Git уже в обновлённом совместимом клиенте. `Update.url` теперь открывает страницу готового выпуска и не является standalone installer.

Если `git apply --check` сообщает конфликт, **не применяй patch с отключёнными проверками и не сбрасывай свои изменения**. Для другой ревизии клиента потребуется перенос SDK-изменения. Простое обновление upstream не гарантирует наличие этого ещё не включённого туда SDK-метода.

## Готовая установленная сборка

Patch предназначен для дерева исходников, а не для `app.asar` или исполняемого файла. Для установленной MSIX/готовой сборки нужен пересобранный клиент с этим SDK-изменением. Подмена файлов установленного приложения здесь не предлагается.

## Откат исходников

Проверь отсутствие собственных более поздних изменений в затронутых файлах, затем используй обратную проверку и откат того же patch:

```powershell
git apply --reverse --check -- $SdkPatch
git apply --reverse -- $SdkPatch
```

После отката требуется обычная пересборка клиента. Возврат исходников не восстанавливает аудио, потерянное при перезапуске.

## Границы

Работу на конкретном Windows-клиенте подтверждает только проверка после установки его новой сборки. Локальные SDK/unit/HTTP/browser проверки не заменяют этот шаг. Отказ при действительно неоднозначном или неизвестном native владельце остаётся безопасным отказом, а не разрешением отправить WAV текущему серверу.

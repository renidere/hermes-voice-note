# Hermes Voice Note

Голосовые вложения прямо в Hermes Desktop: **«Записать» → отправить**, рядом отмена. В ожидании — одна небольшая кнопка с нативной иконкой; во время записи — короткая группа с красной точкой, таймером, тремя штрихами входного сигнала и кнопками-иконками отправки/отмены. Без отдельного рекордера, предварительного распознавания и собственного backend. Плавные переходы учитывают системное уменьшение движения.

## Установка

Для **Windows с удалённым Linux backend** скачай готовый Windows ZIP и запусти **`Start-Voice-Note.cmd`**. **Плагин уже встроен в клиент вместе с нужным SDK; устанавливать его через Git не нужно.** Он появляется как `bundled`, а старая дисковая копия не заменяет его. Полная инструкция: [WINDOWS-CLIENT.ru.md](WINDOWS-CLIENT.ru.md). Переустановка одного плагина в прежнем окне не обновляет SDK этого окна.

**Для Webapp в браузере** плагин устанавливается на обслуживающий host, но SDK patch должен быть собран в фактически обслуживаемый Webapp renderer. Копирование исходников на сервер или перезапуск Python сами по себе не обновляют уже загруженный SDK.

Полный source patch `install/hermes-desktop-session-transport.patch` добавляет session-aware транспорт и исправляет подтверждение приёма сообщения composer. Инструкция сборки из исходников — [SDK-UPDATE.ru.md](SDK-UPDATE.ru.md). Без нужного SDK плагин сообщает требование обновления до появления кнопки; небезопасного старого пути отправки нет.

### Отдельная установка в уже совместимый renderer

Готовому Windows-комплекту эти шаги **не нужны**. Для другого клиента сначала нужен совместимый SDK.

1. Открой **Capabilities → Plugins → Install from Git**.
2. Укажи `https://github.com/renidere/hermes-voice-note`.
3. Выбери Desktop, подтверди установку и включи плагин.

[`install/Install.url`](install/Install.url) открывает страницу выпуска с совместимым комплектом. Он больше не вызывает системный `hermes://`, который мог открыть старый клиент.

### Обновление установленной версии

Сначала **отправь или отмени текущую запись**: обновление выгружает старый экземпляр плагина и освобождает микрофон, несохранённая запись будет потеряна.

Для встроенной Windows-версии скачай новый Windows ZIP, распакуй отдельно и используй его `Start-Voice-Note.cmd`. Это обновляет связанную пару клиент/плагин, не только дисковую копию. [`install/Update.url`](install/Update.url) открывает страницу выпуска, а не произвольный установленный обработчик `hermes://`. Для отдельного плагина в уже совместимом renderer возможна штатная переустановка из Git. Рабочий Python backend перезапускать не требуется.

Установщик получает текущую ветку репозитория и проверенный им commit. Автоматического обновления в фоне плагин не делает. Теги GitHub Releases сохраняют конкретные выпуски, но URL вида `tree/<tag>` **не является способом закрепить версию в текущем установщике**.

## Использование

- Открой **существующий** чат, нажми «Записать» и при необходимости разреши микрофон.
- Для начала записи достаточно сохранённого чата: активный runtime, известный сервер и подключение к нему не требуются. Маршрутизация и соединение проверяются только при явной отправке.
- В Desktop с `retainSession` пустой owner при старте больше не блокирует доставку: SDK вызывает штатный native resolver для исходного ID. Каждый повтор снова разрешает отсутствующего владельца. При действительно неизвестном/неоднозначном native владельце отправка отклоняется без подстановки текущего сервера, а WAV остаётся в памяти.
- Красная точка означает активную запись. Три небольших штриха рядом с таймером реагируют на настоящий входной сигнал, без декоративной пульсации и графиков. Это относительный индикатор активности, не VAD, спектр, измеритель dB или оценка качества микрофона. Плагин берёт максимальный RMS отдельных каналов и не меняет записываемый PCM.
- Разрешение микрофона и загрузка файла имеют отдельные статусы; красная точка и индикатор в эти моменты не показываются. Отправка и отмена — компактные кнопки-иконки с подсказками и доступными именами.
- «Отправить» останавливает захват и отправляет **сам WAV**, не ожидая ASR.
- ID исходного чата и копия известных данных его владельца фиксируются до асинхронного захвата. Native session lease удерживает разрешённое соединение для resume и upload; переключение фокуса не меняет получателя. Если исходный composer уже не виден, вернись в исходный чат и повтори отправку.
- «К отправке» означает, что WAV записан, но сообщение ещё не передано в чат. Принятие `composer.submit` подтверждает очередь UI, не доставку backend или ответ модели.
- Несвязанный текстовый черновик и другие вложения не отправляются и не стираются плагином.
- При ошибке отправки WAV остаётся в памяти для повтора. «Отмена» освобождает микрофон и отменяет последующую отправку сообщения.
- Ошибки записи и отправки показываются также штатным уведомлением Hermes, вне обрезаемой области composer. Различаются микрофон, native-подключение исходного чата, resume, upload и отказ composer. Заблокированный ввод или отсутствие принимающего composer не уничтожают WAV.
- При включённом `prefers-reduced-motion` анимация отключается, красная точка и текстовые статусы остаются.

## Приватность

- Нет телеметрии, сторонних речевых API, загрузки моделей или ASR/LLM-вызовов внутри плагина.
- Аудио идёт в **настроенный пользователем Hermes backend** штатным `file.attach`. После отправки начинается обычный ход чата, который может обратиться к выбранному пользователем модельному провайдеру. Это не обещание полностью локальной обработки всей переписки.
- Неотправленная запись находится в памяти Desktop, не в дисковой библиотеке. Закрытие приложения, отключение и обновление плагина могут её потерять.
- Отмена во время уже начавшегося upload не отзывает байты с сервера: файл может остаться среди backend-вложений, хотя сообщение в чат не отправлено.
- В репозиторий и релизы не входят пользовательские записи, локальные отчёты, ключи, адреса частной инфраструктуры и старая внутренняя Git-история.

## Формат и ограничения

- PCM16 WAV, до двух каналов; без собственного усиления, фильтров и сведения каналов. Реальное число каналов зависит от устройства и браузера.
- `echoCancellation`, `noiseSuppression`, `autoGainControl` запрашиваются выключенными. Если трек явно сообщает включённую обработку, захват отклоняется. Отсутствующие настройки не доказывают отсутствие DSP; аппаратную обработку плагин не контролирует.
- Частота WAV соответствует `AudioContext`; браузер может ресемплировать вход. Float32 → PCM16 квантует сигнал: это не bit-exact захват АЦП.
- До **5 минут или 64 MiB PCM**. На лимите захват прекращается; отправка остаётся явным действием пользователя.
- Первый аудиопост в совершенно пустой новой сессии пока не поддержан: нужна существующая сессия для upload.
- Используется поддерживаемый нынешним клиентом, но устаревающий `ScriptProcessorNode`; будущая замена на AudioWorklet потребует отдельной проверки.

## Разработка и проверки

Runtime — один `plugin.js`, без сборки и установки npm-пакетов. `private: true` в `package.json` предотвращает случайную публикацию в npm и не относится к публичности GitHub.

Для тестов используются Node, `jsdom`, React и ReactDOM как devDependencies; runtime по-прежнему использует React, предоставленный Hermes.

```sh
npm ci
npm test
npm run test:dom
```

Тесты исполняют настоящий модуль с fixture SDK и аудиограницами. DOM-регрессия проверяет настоящие `button.click()` внутри формы: Record/Send/Cancel не должны отправлять несвязанный черновик. Это не эмуляция всей оболочки Hermes.

Дополнительный Linux smoke требует установленный Chromium/Chrome и `/usr/bin/ffmpeg`, `/usr/bin/ffprobe`:

```sh
npm run test:browser
```

Он использует синтетический микрофон, локальный fixture receiver и не вызывает модель. Создаваемые аудио/логи сохраняются в игнорируемом `evidence/` и не публикуются. Границы опубликованных проверок описаны в [VALIDATION.md](VALIDATION.md).

Дополнительная проверка UI с настоящим SDK Button требует checkout Hermes с установленными frontend-зависимостями (`esbuild`, React/ReactDOM) и Chrome:

```sh
HERMES_SOURCE_ROOT=/path/to/hermes-agent npm run test:ui-browser
```

Этот opt-in smoke проверяет normal/reduced motion, динамическую смену настройки, стабильность DOM и изоляцию CSS. Его оболочка/тема и host остаются fixtures; он не заменяет нативный Desktop E2E. Неиспользуемая ветка иконки загрузки SDK Button в harness заглушена.

Совместная проверка с настоящим новым SDK-модулем требует checkout с применённым SDK patch и `esbuild`:

```sh
HERMES_SOURCE_ROOT=/path/to/patched-hermes-agent npm run test:native
```

Она исполняет настоящий session lease, native sync owner ladder, router и ambiguity guard, отправляет WAV двум настоящим loopback HTTP receivers и проверяет исходный composer ID, retry и отсутствие запросов к чужому источнику. Store lookup и pooled-socket I/O — явно заданные адаптеры. Это не исполнение async REST-discovery, Windows/Electron или финального модельного хода.

## Удаление

Отключи/удали «Голосовые сообщения» в Plugins. Микрофон будет освобождён, уже отправленные backend-вложения останутся.

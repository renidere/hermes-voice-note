# Windows-клиент с Voice SDK

Это **неофициальная portable-сборка Hermes Light для Windows x64**. Она предназначена для подключения к уже работающему удалённому Hermes backend. Собственного Python backend в ней нет.

Сборка содержит полный SDK/composer patch, необходимый `hermes-voice-note` 0.4.x. Обычная переустановка плагина в прежнем клиенте этот SDK не добавляет.

## Установка

1. Скачай из GitHub Release файл **`Hermes-Voice-SDK-Windows-x64.zip`** и `WINDOWS-SHA256SUMS`.
2. Сверь SHA-256 архива с опубликованной суммой. Например, в PowerShell:

   ```powershell
   Get-FileHash .\Hermes-Voice-SDK-Windows-x64.zip -Algorithm SHA256
   ```

3. Распакуй **весь** архив в отдельную папку. Не переноси только `.exe`: ему нужны соседние `resources`, DLL и остальные файлы.
4. Запусти **`hermes-light-3b42157.exe`** из этой папки. Это отдельная сборка с именем `Hermes Light 3b42157`; основную установленную версию Hermes удалять не нужно. Не запускай вместо неё старый ярлык Hermes.
5. Подключи тот же Linux backend штатным диалогом подключения. Эта сборка имеет отдельную desktop identity и не должна заменять настройки основной stable-установки. Данные чатов на Linux backend не переносятся и не удаляются.
6. В **этом новом окне** открой `Capabilities → Plugins`. Если `hermes-voice-note` уже установлен, включи его. Если его нет, выбери `Install from Git` и укажи репозиторий `https://github.com/renidere/hermes-voice-note`.
7. Открой существующий чат и проверь кнопку записи. Затем проверь короткую запись и её отправку именно в исходный чат.

Не используй `Install.url`/`Update.url` для выбора этой сборки: системный обработчик `hermes://` может открыть прежнюю установку. Диалог установки внутри правильного окна исключает эту путаницу.

## Подпись и сохранность данных

- Это не официальный подписанный установщик Nous. Windows/SmartScreen или корпоративные политики могут ограничить запуск. Не отключай глобальную защиту Windows ради установки. При обязательной проверке подписи потребуется доверенная подписанная сборка или установленная администратором процедура допуска.
- Commit-вариант имеет отдельное имя приложения и не использует обычный канал автоматических обновлений stable-клиента. Архив не должен распаковываться поверх существующей установки.
- Не закрывай прежний клиент, пока нужна несохранённая запись в его памяти. Старый WAV не переносится в новое окно автоматически.
- После нажатия «Отправить» начинается обычный ход чата с настроенным пользователем модельным провайдером. CI-сборка сама не вызывает этот провайдер и не получает пользовательские конфиги, ключи или записи.

## Происхождение и проверка

- Core base: `NousResearch/hermes-agent`, commit `3b421578588243f920886e6fe79a6faa87ea026e`.
- Дополнение: полный `install/hermes-desktop-session-transport.patch`, включая session lease и фактический ACK composer.
- `windows-client-source.json` закрепляет SHA-256 patch и всех изменённых исходников. Base commit **сам по себе не идентифицирует** эту изменённую сборку; нужен также patch hash.
- `windows-build.json` связывает ZIP с конкретным Windows workflow/run и его контрольной суммой.
- CI проверяет SDK/composer и плагин на Windows, собирает renderer и native-часть, затем проверяет пакет, Windows x64 executable и наличие нового SDK в упакованных файлах. Это не проверка конкретного микрофона, пользовательского окна или доставки записи в пользовательский backend.

При проблеме важны имя открытого приложения и точный текст ошибки. Повторная установка плагина в старый клиент не является обновлением SDK.

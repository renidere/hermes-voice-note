# Windows: клиент с уже встроенными голосовыми сообщениями

Это неофициальная portable-сборка **Hermes Light 3b42157**, Windows x64. Она подключается к существующему удалённому backend. Собственного Python backend в ней нет.

**`hermes-voice-note` уже встроен в клиент и включается штатным механизмом bundled plugins. Устанавливать его через Git, переносить `plugin.js` или применять SDK patch вручную не нужно.** SDK, подтверждение composer и сам плагин собираются вместе. Старая дисковая копия с тем же ID не заменяет встроенную: Hermes показывает её как `stale disk copy`, не удаляя файлы.

## Запуск

1. Скачай `Hermes-Voice-SDK-Windows-x64.zip` и `WINDOWS-SHA256SUMS` из одного выпуска. При необходимости сверь сумму:

   ```powershell
   Get-FileHash .\Hermes-Voice-SDK-Windows-x64.zip -Algorithm SHA256
   ```

2. Распакуй **весь архив** в новую папку. Не копируй один `.exe` и не распаковывай поверх stable-установки.
3. Дважды щёлкни **`Start-Voice-Note.cmd`**. Он запускает именно соседний совместимый EXE. PowerShell-установщик, npm, Git и права администратора для этого не нужны.
4. При первом запуске подключи свой Linux backend обычным диалогом. Старые настройки и ключи автоматически не копируются; это намеренная изоляция, не удаление чатов на сервере.
5. Открой существующий чат. Кнопка «Записать» предоставляется встроенным плагином. В `Capabilities → Plugins` у него должен быть тип **bundled**. Если ты сам ранее выключил его в этом клиенте, включи обычным переключателем.

Используй этот же `Start-Voice-Note.cmd` для следующих запусков и ярлыков. Не подменяй его старым ярлыком Hermes или системной ссылкой `hermes://`.

## Что делает launcher

- Задаёт только переменные дочернего процесса, не меняет системное окружение или registry.
- Использует отдельные desktop-настройки в `%LOCALAPPDATA%\HermesVoiceNote\desktop` и отдельный `hermes-home` внутри этой папки.
- Не перехватывает системный `hermes://` у основной установки.
- Не скачивает и не устанавливает плагин: нужная версия уже находится в renderer самого клиента.
- Не копирует настройки, ключи и записи из прежней установки; не удаляет её и не закрывает её окна.

При открытии bare EXE SDK и плагин также встроены, но изоляция путей и отказ от регистрации `hermes://` задаются launcher. Поэтому рекомендуемая точка входа — именно `.cmd`.

## Ограничения

- Сборка unsigned, без официальной подписи Nous. Windows/SmartScreen и корпоративные политики могут ограничивать запуск. Не отключай глобальную защиту Windows ради этого ZIP.
- Не закрывай прежнее окно с несохранённым WAV: запись хранится в RAM и не переносится между клиентами.
- Commit-вариант не использует обычный stable update feed. Основную установленную версию Hermes удалять не нужно.
- Реальный микрофон и отправка в твой конкретный старый/переименованный чат требуют отдельной пользовательской проверки. CI не получает пользовательские конфиги/аудио и не вызывает модельных или речевых провайдеров.

## Происхождение

Core base: `NousResearch/hermes-agent`, commit `3b421578588243f920886e6fe79a6faa87ea026e`. Полный SDK/composer patch закреплён в `install/hermes-desktop-session-transport.patch`; файл плагина дополнительно помещается в штатный `src/plugins/hermes-voice-note/plugin.js` перед build. `windows-client-source.json` содержит hashes всех девяти исходников, включая этот файл. Base SHA без patch hash не идентифицирует сборку. `windows-build.json` связывает пакет с фактическим CI run и его checksum.
